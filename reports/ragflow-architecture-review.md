# RAGFlow architecture review

**Decision: retain WeHPAH!’s current architecture.** RAGFlow is a capable, broader retrieval platform, but the available evidence does not show that replacing the existing static application would improve legal evidence retrieval or citation accuracy enough to justify operating its server stack. This is an architectural assessment, not a measured comparison of retrieval quality.

Reviewed RAGFlow source at commit [`3c6d2255af06164f0818d0959af10de0afd8b8fa`](https://github.com/infiniflow/ragflow/commit/3c6d2255af06164f0818d0959af10de0afd8b8fa), together with the local WeHPAH! ingestion and browser code. The repository was inspected through the GitHub connector; a local clone could not resolve GitHub DNS. No production files or datasets were changed.

| Question | WeHPAH! today | RAGFlow and assessment |
| --- | --- | --- |
| Distribution and operations | Static browser application, public dataset, browser-side retrieval and PDF rendering. | The [Go deployment](https://github.com/infiniflow/ragflow/blob/3c6d2255af06164f0818d0959af10de0afd8b8fa/docker/README.md) runs API, admin, ingestor and syncer services, with a default dependency profile including Elasticsearch, MySQL, MinIO, Kvrocks, NATS and ClickHouse. The [quickstart](https://github.com/infiniflow/ragflow/blob/3c6d2255af06164f0818d0959af10de0afd8b8fa/docs/quickstart.mdx) recommends 4 CPU cores, 16 GB RAM and 50 GB disk as a starting configuration. This changes the operating model and introduces hosting, maintenance and availability costs. |
| Retrieval | Literal verification after keyword candidate retrieval; concept search routes to selected Parquet shards. | [Retrieval testing](https://github.com/infiniflow/ragflow/blob/3c6d2255af06164f0818d0959af10de0afd8b8fa/docs/guides/dataset/retrieval_testing.md) supports weighted keyword and semantic search and optional reranking. These are plausible improvements, but recall, ranking, latency and cost on this dossier have not been measured. Routing only to selected clusters may miss relevant passages in other clusters. |
| Evidence and determinism | Extractive answer claims pass a verbatim substring gate; normalized passage coordinates drive PDF overlays. A matching quotation does not itself establish that a paraphrased claim is entailed, and OCR and retrieval can still omit evidence. | [Citation code](https://github.com/infiniflow/ragflow/blob/3c6d2255af06164f0818d0959af10de0afd8b8fa/internal/service/chat_pipeline.go) passes source positions in citation data. This does not by itself prove equivalent page, bounding-box or quote-verification behavior. Generated answers and model choices require independent validation. |
| Ingestion | Existing Docling/OCR processing, embeddings, normalized coordinates and release manifests are already in place. | DeepDoc is a parsing component, not the whole platform. The [deployment documentation](https://github.com/infiniflow/ragflow/blob/3c6d2255af06164f0818d0959af10de0afd8b8fa/docker/README.md) describes CPU-based, in-process layout analysis, OCR and table recognition. Reusing existing passage IDs, text, embeddings and normalized page boxes in RAGFlow has not been demonstrated; reparsing could alter evidence boundaries. |
| Privacy | The current public dataset is public; query and artifact exposure depend on the services contacted by the browser. | Self-hosting can provide control over storage and models, but privacy depends on configuration, access controls and any external model provider. It would not automatically make the current public corpus private. |

## Test decision and remaining evidence

No full RAGFlow prototype was run: the review found no demonstrated benefit that would justify deploying the multi-service stack and re-ingesting a corpus merely to establish architectural fit. No comparative accuracy, resource, latency, price, repeatability or citation measurements are claimed.

A lower-cost next step is to build a representative, manually judged set of legal questions and difficult pages, including scanned text, tables and citations. Measure passage recall and ranking, transcription and table accuracy, correct page and overlay placement, repeatability, latency and resource use. First compare current retrieval with alternatives using the same passages; separately compare DeepDoc against Docling on known extraction failures. Preserve the existing passage provenance and quote gate in any isolated test. Consider a full-platform trial only if these results identify a material benefit that cannot be obtained within the current delivery model.
